# Decisions and verified assumptions

Decisions made without asking, as section 2 of the engineering brief (2026-10-28) allows. Each entry gives one line of reasoning. Newest entries are at the bottom of each section.

## Phase 0: Neon port

| #   | Decision                                                                                                                                                                                                                         | Reasoning                                                                                                                                                                                                                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Owners live in `public.owners(auth_provider, auth_subject)`, and ledger foreign keys reference that table instead of Neon Auth's user table.                                                                                     | The ledger does not depend on Neon Auth's internal schema, and the same owner row can later be reached through MCP OAuth.                                                                                                                                                                                              |
| D2  | Identity is the transaction-local setting `app.owner_id`, set with `set_config(..., true)` inside each request transaction.                                                                                                      | Transaction-local settings are discarded at commit, so a pooled connection cannot carry one owner's identity into another request. A test covers this.                                                                                                                                                                 |
| D3  | The app connects as a separate login role, `perkkeep_app` (no `BYPASSRLS`, no superuser, owns nothing), through `PERKKEEP_DATABASE_URL`. Each pool checks those three properties on first use and refuses to serve if any fails. | Brief section 4 forbids serving user queries under the owner role. A separate login role is stronger than `SET ROLE`, which a later `RESET ROLE` can undo.                                                                                                                                                             |
| D4  | Every ledger table uses `FORCE ROW LEVEL SECURITY`.                                                                                                                                                                              | A future table owner without `BYPASSRLS` would otherwise skip the policies silently.                                                                                                                                                                                                                                   |
| D5  | The browser calls a fixed list of named operations (`/api/ledger`). It never sends SQL, table names, or column lists. Evidence entered in the app is always recorded as `recorded_by = 'user'`.                                  | This keeps the attack surface small and stops a client from forging import or inference provenance.                                                                                                                                                                                                                    |
| D6  | Sessions are verified on the server with Neon Auth `getSession()`, with the signed session-data cookie cache set to 60 seconds (the default is 300).                                                                             | This shortens the window in which a revoked session still opens the ledger, at the cost of more upstream session checks.                                                                                                                                                                                               |
| D7  | Access requires a verified email address that appears in `PERKKEEP_OWNER_EMAILS`. An empty list admits nobody.                                                                                                                   | This gives "private owner access only" that fails closed, whatever sign-up settings Neon Auth has.                                                                                                                                                                                                                     |
| D8  | State-changing routes require an `Origin` in the allowed list (Vercel system URLs plus `PERKKEEP_ALLOWED_ORIGINS`) and `Sec-Fetch-Site: same-origin` when the browser sends it.                                                  | Cookie-authenticated routes need cross-site request protection.                                                                                                                                                                                                                                                        |
| D9  | A synthetic test identity provider exists for local tests only. It turns off on Vercel and with a non-local database, and the build guard rejects it.                                                                            | Neon Auth sets `__Secure-` cookies and calls a hosted service, so local browser tests cannot use it.                                                                                                                                                                                                                   |
| D10 | Migrations run manually (`npm run db:migrate`, `npm run neon:provision`) over the direct (unpooled) connection, never during a Vercel build.                                                                                     | A preview build must not change the production schema, and session advisory locks need a direct connection.                                                                                                                                                                                                            |
| D11 | Supabase is removed from the app's runtime code. `supabase/` and the CLI stay as `legacy:supabase:*` scripts.                                                                                                                    | The ported suite passes on the Postgres path (brief section 4). The legacy stack is still needed to export the owner's existing local ledger.                                                                                                                                                                          |
| D12 | The snapshot API returns the newest 1,000 audit events.                                                                                                                                                                          | All audit rows stay in the database, and the cap keeps the 60-second refresh bounded as history grows.                                                                                                                                                                                                                 |
| D13 | The seven low-severity audit findings are left in place.                                                                                                                                                                         | All seven trace to one advisory (GHSA-gcqx-w48m-w2h4, `deepmerge`) reached through `@neondatabase/auth-ui` email rendering. PerkKeep imports none of these packages, the built `.next` output contains none of their code, and the only fix is a semver-major change.                                                  |
| D14 | The SimpleFIN setup token was not claimed from the cloud agent container.                                                                                                                                                        | A setup token can be claimed only once ([SimpleFIN developer guide](https://beta-bridge.simplefin.org/info/developers)), the container is temporary, and the brief does not name the container as a destination for real financial data. The token belongs in the owner-only settings page once that page is deployed. |
| D15 | Card art (section 8a) will be stored in Neon as owner-scoped bytes under the same row-level security, and served with `no-store`.                                                                                                | Neon is already private infrastructure named in the brief, so no extra storage service or plan is needed.                                                                                                                                                                                                              |
| D16 | `neon:provision --vercel` writes production variables only.                                                                                                                                                                      | `vercel env add` for preview can ask which branch to target. Preview builds fail closed at the guard until preview variables exist.                                                                                                                                                                                    |
| D17 | Generated database passwords use 192 random bits plus fixed character classes.                                                                                                                                                   | Neon's role documentation asks for mixed character classes in SQL-set passwords.                                                                                                                                                                                                                                       |

## Phase 1: sources, and section 8a: card art

| #   | Decision                                                                                                                                                                                                                                                                                                                                                 | Reasoning                                                                                                                                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D18 | Accounts and transactions store keyed digests (HMAC-SHA-256) of source identifiers, never the raw ids. The digest key is derived from `PERKKEEP_ENCRYPTION_KEY` with HKDF.                                                                                                                                                                               | Brief section 5 forbids storing raw source payloads. Rotating that key will need a re-keying migration, which is recorded here so it is not done casually.                              |
| D19 | Transactions form one linear revision chain per source reference (`observed`, then `revised` or `removed`). For SimpleFIN, which reports no removals, a pending charge that disappears from a window the source returned in full is recorded as `removed`. Posted charges are never inferred as removed.                                                 | Brief section 5 requires pending-to-posted changes and removals to be linked corrections, never deletions. A pending charge replaced by a posted one under a new id is the common case. |
| D20 | The first sync requests 90 days; later syncs overlap the last success by 14 days. Coverage starts at the requested window and ends at the source's own last refresh date (`balance-date`), not the day the sync ran.                                                                                                                                     | SimpleFIN refreshes about once a day, so "synced today" would overstate coverage. SimpleFIN may return less history than requested, so the UI labels coverage as the requested window.  |
| D21 | CSV files import only into CSV accounts. Deduplication between a CSV account and an aggregator account for the same card is deferred to the Phase 2 matchers.                                                                                                                                                                                            | Rows from different sources have no shared identifier, so merging them safely needs matching logic, not a database key.                                                                 |
| D22 | A CSV import's idempotency key is the file's SHA-256. A digest of the target account, format and parsed rows detects a replay of the same file with different settings, which is rejected.                                                                                                                                                               | This implements "replaying the same file creates nothing new; a different file with the same key is rejected" (brief section 5).                                                        |
| D23 | When two layouts share the same columns (Amex and generic `Date, Description, Amount`), the owner must choose the layout, because the sign conventions differ. Issuer layouts are labeled unverified until a real file of each kind has imported correctly. Copilot Money is unsupported until a sample exists.                                          | A wrong sign would turn every purchase into a credit.                                                                                                                                   |
| D24 | Mapping is proposed only when the institution matches the card's issuer and exactly one card has the same last four digits. The owner confirms every link, and the unidentified Chase record is never assumed to be an Ink card.                                                                                                                         | Brief section 5.                                                                                                                                                                        |
| D25 | Daily sync runs at 10:23 UTC (`vercel.json`). The cron route requires `CRON_SECRET` and returns counts only.                                                                                                                                                                                                                                             | Hobby allows one run per day (see the section 14 table).                                                                                                                                |
| D26 | The Plaid adapter calls Sandbox only and refuses any other `PLAID_ENV`. It has not run against Plaid.                                                                                                                                                                                                                                                    | Brief section 5. No Plaid credentials are available here.                                                                                                                               |
| D27 | Card art is stored in Neon (`card_art`, owner-scoped bytes under row-level security), normalized with `sharp` to 1012×638 WebP (1.586:1), and served only by an authenticated route with `Cache-Control: private, no-store`.                                                                                                                             | Brief section 8a allows private storage on Neon, which needs no new service or plan.                                                                                                    |
| D28 | The server fetches issuer art only from URLs listed in `data/card-faces.json`, never from a URL in the request. Images with a baked-in "No annual fee" badge (Freedom Unlimited, both Prime Visa variants found) and Discover's only image (it includes a drop shadow) were not used; those cards keep the placeholder until the owner uploads an image. | Brief section 8a forbids images that include a badge. The listed URLs were found by inspecting each product page's network requests on 2026-10-28.                                      |
| D29 | Bands in each card's sampled color cover sample names baked into issuer images ("C F FROST", "D. BARRETT", "BARRETT CONNECT"), and on Gold also the sample "7997" and "09".                                                                                                                                                                              | The owner's name and last four are drawn in those places instead (brief section 8a).                                                                                                    |
| D30 | The overlay name is the owner's Neon Auth profile name. Account creation asks for it, and Settings can change it.                                                                                                                                                                                                                                        | Brief section 8a: pulled from the profile, never hard-coded.                                                                                                                            |
| D31 | Three badge text colors were darkened (to contrast ratios of 5.4 to 5.8).                                                                                                                                                                                                                                                                                | The Settings accessibility audit found the earlier amber badge below WCAG AA contrast.                                                                                                  |
| D32 | The build guard fails every Vercel build on an unsafe setting, but fails only production builds on missing settings. A preview without settings builds and shows the setup screen.                                                                                                                                                                       | The Vercel project builds every pushed branch. A preview with no settings opens no data, and production must never deploy half-configured.                                              |

| SimpleFIN Bridge sources connections from MX.                                                    | Not verified.
