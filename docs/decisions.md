# Decisions and verified assumptions

Decisions made without asking, as section 2 of the engineering brief (2026-10-28) allows. Each entry gives one line of reasoning. Newest entries are at the bottom of each section.

## Phase 0: Neon port

| #   | Decision                                                                                                                                                                                                                         | Reasoning                                                                                                                                                                                                                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Owners live in `public.owners(auth_provider, auth_subject)`, and ledger foreign keys reference that table instead of Neon Auth's user table.                                                                                     | The ledger does not depend on Neon Auth's internal schema, and the same owner row can later be reached through MCP OAuth.                                                                                                                                                                                              |
| D2  | Identity is the transaction-local setting `app.owner_id`, set with `set_config(..., true)` inside each request transaction.                                                                                                      | Transaction-local settings are discarded at commit, so a pooled connection cannot carry one owner's identity into another request. A test covers this.                                                                                                                                                                 |
| D3  | The app connects as a separate login role, `perkkeep_app` (no `BYPASSRLS`, no superuser, owns nothing), through `PERKKEEP_DATABASE_URL`. Each pool checks those three properties on first use and refuses to serve if any fails. | Brief section 4 forbids serving user queries under the owner role. A separate login role is stronger than `SET ROLE`, which a later `RESET ROLE` can undo.                                                                                                                                                             |
| D4  | Every ledger table uses `FORCE ROW LEVEL SECURITY`.                                                                                                                                                                              | A future table owner without `BYPASSRLS` would otherwise skip the policies silently.                                                                                                                                                                                                                                   |
| D5  | The browser calls a fixed list of named operations (`/api/ledger`). It never sends SQL, table names, or column lists. Evidence entered in the app is always recorded as `recorded_by = 'user'`.                                  | This keeps the attack surface small and stops a client from forging import or inference provenance.                                                                                                                                                                                                                    |
| D6  | Sessions are verified on the server with Neon Auth `getSession()`, with the signed session-data cookie cache set to 60 seconds (the default is 300).                                                                             | This shortens the window in which a revoked session still opens the ledger, at the cost of more upstream session checks.                                                                                                                                                                                               |
| D7  | Access requires a verified email address that appears in `PERKKEEP_OWNER_EMAILS`. An empty list admits nobody.                                                                                                                   | This gives "private owner access only" that fails closed, whatever sign-up settings Neon Auth has.                                                                                                                                                                                                                     |
| D8  | State-changing routes require an `Origin` in the allowed list (Vercel system URLs plus `PERKKEEP_ALLOWED_ORIGINS`) and `Sec-Fetch-Site: same-origin` when the browser sends it.                                                  | Cookie-authenticated routes need cross-site request protection.                                                                                                                                                                                                                                                        |
| D9  | A synthetic test identity provider exists for local tests only. It turns off on Vercel and with a non-local database, and the build guard rejects it.                                                                            | Neon Auth sets `__Secure-` cookies and calls a hosted service, so local browser tests cannot use it.                                                                                                                                                                                                                   |
| D10 | Migrations run manually (`npm run db:migrate`, `npm run neon:provision`) over the direct (unpooled) connection, never during a Vercel build.                                                                                     | A preview build must not change the production schema, and session advisory locks need a direct connection.                                                                                                                                                                                                            |
| D11 | Supabase is removed from the app's runtime code. `supabase/` and the CLI stay as `legacy:supabase:*` scripts.                                                                                                                    | The ported suite passes on the Postgres path (brief section 4). The legacy stack is still needed to export the owner's existing local ledger.                                                                                                                                                                          |
| D12 | The snapshot API returns the newest 1,000 audit events.                                                                                                                                                                          | All audit rows stay in the database, and the cap keeps the 60-second refresh bounded as history grows.                                                                                                                                                                                                                 |
| D13 | The seven low-severity audit findings are left in place.                                                                                                                                                                         | All seven trace to one advisory (GHSA-gcqx-w48m-w2h4, `deepmerge`) reached through `@neondatabase/auth-ui` email rendering. PerkKeep imports none of these packages, the built `.next` output contains none of their code, and the only fix is a semver-major change.                                                  |
| D14 | The SimpleFIN setup token was not claimed from the cloud agent container.                                                                                                                                                        | A setup token can be claimed only once ([SimpleFIN developer guide](https://beta-bridge.simplefin.org/info/developers)), the container is temporary, and the brief does not name the container as a destination for real financial data. The token belongs in the owner-only settings page once that page is deployed. |
| D15 | Card art (section 8a) will be stored in Neon as owner-scoped bytes under the same row-level security, and served with `no-store`.                                                                                                | Neon is already private infrastructure named in the brief, so no extra storage service or plan is needed.                                                                                                                                                                                                              |
| D16 | `neon:provision --vercel` writes production variables only.                                                                                                                                                                      | `vercel env add` for preview can ask which branch to target. Preview builds fail closed at the guard until preview variables exist.                                                                                                                                                                                    |
| D17 | Generated database passwords use 192 random bits plus fixed character classes.                                                                                                                                                   | Neon's role documentation asks for mixed character classes in SQL-set passwords.                                                                                                                                                                                                                                       |

## Section 14 assumptions, checked 2026-10-28

| Assumption                                                                                       | Finding                                                                                                                                                                                                                                                                                                                                                   | Source                                                                                                                          |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Copilot Money exports transactions as CSV.                                                       | Confirmed by Copilot's help center: Settings, Account, "Export your transactions" produces a CSV. Column format not yet seen; a sample is still needed.                                                                                                                                                                                                   | [Copilot help: exporting your transaction data](https://help.copilot.money/en/articles/5944414-exporting-your-transaction-data) |
| Claude.ai custom connectors accept a remote MCP server with OAuth and allow write tools.         | OAuth is confirmed. Claude supports DCR (RFC 7591) and CIMD by default, sends S256 PKCE on every authorization request, discovers the authorization server through RFC 9728 protected resource metadata after a `401`, and uses the callback `https://claude.ai/api/mcp/auth_callback`. Write tools are not addressed on that page and remain unverified. | [Claude docs: Authentication for connectors](https://claude.com/docs/connectors/building/authentication)                        |
| ChatGPT connectors accept a remote MCP server with OAuth.                                        | Not checked yet (Phase 2).                                                                                                                                                                                                                                                                                                                                | Not checked                                                                                                                     |
| Vercel Hobby cron runs at most once per day.                                                     | Confirmed by Vercel's usage page: Hobby cron jobs run once per day, and timing can vary within the scheduled hour.                                                                                                                                                                                                                                        | [Vercel: Cron jobs usage and pricing](https://vercel.com/docs/cron-jobs/usage-and-pricing)                                      |
| SimpleFIN Bridge sources connections from MX.                                                    | Not verified. The protocol documents only the setup-token claim and the `/accounts` endpoint.                                                                                                                                                                                                                                                             | [SimpleFIN protocol](https://www.simplefin.org/protocol.html)                                                                   |
| Chase and American Express connect reliably through SimpleFIN.                                   | Not verifiable without the owner's accounts. The design treats sync failures as stale coverage, not as errors.                                                                                                                                                                                                                                            | Not checked                                                                                                                     |
| iOS does not let third-party apps select the Apple Pay card.                                     | Not checked yet (Phase 3).                                                                                                                                                                                                                                                                                                                                | Not checked                                                                                                                     |
| Neon: roles created with SQL do not get `BYPASSRLS`; `neondb_owner` belongs to `neon_superuser`. | Confirmed by Neon's documentation. `neon_superuser` includes `BYPASSRLS` only in projects created after that change, so `neon:provision` reports the owner's attribute instead of assuming it.                                                                                                                                                            | [Neon: Manage roles](https://neon.com/docs/manage/roles/)                                                                       |
